# MinistryOfMusic — магазин музыкальных инструментов

Next.js App Router, React, TypeScript strict, Tailwind CSS, компоненты shadcn/ui, lucide-react, Prisma **v6**, PostgreSQL, Auth.js, Zod и Zustand. Интерфейс на русском в теме Soft Black & Gold.

## Локальный запуск

Команды для PowerShell (суффикс `.cmd` позволяет работать без изменения политики выполнения сценариев):

```powershell
npm.cmd install
Copy-Item .env.example .env # только если .env ещё нет
npm.cmd run setup:env
docker compose up -d
npx.cmd prisma db push
npm.cmd run db:seed
npm.cmd run dev
```

Откройте [localhost:3000](http://localhost:3000). В `.env` нужны `DATABASE_URL`, случайный `AUTH_SECRET` и `AUTH_URL`. Команда `setup:env` создаёт секрет, не выводит его и сохраняет существующее непустое значение. Файл `.env` не хранится в Git. При смене адреса сервера обновите `AUTH_URL`.

Seed добавляет исходные три категории, четыре бренда и шесть товаров. Повторный запуск сохраняет заказы, пользователей, остатки и изменения товаров; исправляются только исходные ссылки-заглушки фотографий. Денежные поля хранят целые **рубли**.

## Аккаунты и администратор

Зарегистрируйтесь на `/register`, затем войдите на `/login`. Общедоступная регистрация всегда создаёт роль `USER`. Пароли хешируются bcrypt; сессии Auth.js хранятся в HTTP-only cookie. Вход ограничен 20 попытками на почту за 15 минут, регистрация — 20 попытками за 15 минут на источник. Лимиты хранятся в PostgreSQL; записи старше суток удаляются при следующем обращении.

Выдать права существующему аккаунту можно только локально:

```powershell
npm.cmd run admin:grant -- your-email@example.com
```

Админка находится на `/admin`, ссылка также появится в профиле. Роль проверяется в базе на каждой защищённой странице и в каждом действии; изменение JWT или скрытых полей формы не даёт прав администратора. Готовых аккаунтов и общих паролей администратора нет.

Если приложение работает за доверенным reverse proxy, который **перезаписывает** `x-forwarded-for`, можно включить `TRUST_PROXY=true` для раздельного ограничения регистраций по источнику. Без этого все регистрации имеют общий лимит. Для production настройте HTTPS и корректный `AUTH_URL`; демонстрационные реквизиты PostgreSQL из Compose предназначены для локальной разработки.

## Что реализовано

- `/`: категории, избранные товары, бренды, переходы в каталог.
- `/catalog`: поиск, категория, бренд, диапазон цен, наличие, сортировка и пагинация через URL. Параметры проверяются Zod.
- `/product/[slug]`: галерея, описание, характеристики JSON, цены и добавление в корзину.
- `/cart`: корзина гостя в localStorage, корзина аккаунта в БД, количество и удаление. После входа гостевые товары объединяются с серверной корзиной; повторная отправка одного переноса не создаёт дубликатов. Текущие цены и остатки при переносе берутся с сервера.
- `/profile`: история заказов с пагинацией и уведомления; изменение имени, телефона и адреса по умолчанию; смена пароля с завершением предыдущих сеансов. Данные автоматически подставляются в оформление. `/profile/orders/[id]` — подробности своего заказа, история изменений, условия доставки, отмена неоплаченного заказа и повтор заказа по текущим ценам. Повтор атомарно добавляет все позиции в корзину только при достаточном наличии.
- `/favorites`: избранное до 100 товаров, сохраняется в этом браузере через Zustand/localStorage; синхронизации избранного между устройствами пока нет. `/compare?ids=...` — сравнение до 4 опубликованных товаров по цене, бренду, наличию и характеристикам. Ссылка на сравнение доступна возле кнопок выбора товара; избранное — в подвале сайта.
- Каталог поддерживает точный фильтр по характеристике через URL, включая числовые и логические значения. Список вариантов формируется из опубликованных товаров выбранной категории (до 200 вариантов).
- В карточке доступны отзывы с рейтингом после получения заказа и вопросы авторизованных покупателей. Сообщения проходят модерацию в `/admin?tab=feedback`. Вопрос публикуется вместе с ответом магазина. Изменённый отзыв отправляется на проверку повторно. На странице показаны последние 20 опубликованных отзывов и вопросов.
- Совместимые аксессуары назначает администратор в редакторе товара (до 8 артикулов); совместимость проверяется вручную. Неопубликованные аксессуары не показываются.
- `/delivery` описывает текущий порядок согласования заказа. `/sitemap.xml`, `/robots.txt`, канонические ссылки товаров, описания, Open Graph и JSON-LD подготовлены. Перед публикацией задайте реальный публичный `SITE_URL` (по умолчанию используется `AUTH_URL`).
- `/admin`: управление товарами, категориями и брендами; поиск, фильтры и пагинация товаров и заказов. У товара есть состояния «Черновик», «Опубликован», «Архив». В каталоге и оформлении доступны только опубликованные товары. Характеристики редактируются полями «название — значение».
- Фотографии загружаются из админки: JPEG, PNG, WebP до 8 МБ и 40 Мп, до 8 фото на товар. Сервер проверяет содержимое, преобразует в WebP до 1800×1800 и удаляет метаданные. Изображения хранятся в таблице `Media`, доступны по `/media/[id]` и входят в резервную копию БД. Можно переставлять фотографии и убирать их из карточки. Загрузка файла сама по себе не публикует товар. Удаление из карточки не удаляет файл из библиотеки БД.

Заказ создаётся в сериализуемой транзакции: сумма товаров считается по ценам БД, цена, название и артикул фиксируются в позиции, остатки уменьшаются атомарно, корзина очищается. Повтор запроса с тем же идентификатором возвращает существующий заказ. Для старых заказов без снимка названия отображается текущая карточка.

Товары резервируются на 24 часа. Фоновый обработчик раз в минуту отменяет просроченные неоплаченные заказы. Отмена покупателем, администратором и обработчиком возвращает остаток ровно один раз, даже при одновременных запросах. Старые заказы без `reservedUntil` автоматически не отменяются. Остаток в кэшированном каталоге после фоновой отмены обновляется при очередной минутной ревалидации; оформление всегда проверяет БД.

`npm.cmd run dev` и `npm.cmd start` запускают сайт вместе с обработчиком резервов. Если Next.js запускается напрямую, отдельно запустите `npm.cmd run orders:worker` под менеджером процессов. Однократная обработка: `npm.cmd run orders:worker -- --once`. При обновлении уже работающего сервера его нужно перезапустить командой `npm.cmd run dev`, чтобы запустился обработчик. На платформе без постоянных процессов нужен отдельный фоновый сервис или планировщик.

Проверка без изменений данных: `npm.cmd run orders:worker -- --once --dry-run`. Для проверки совместного запуска в режиме чтения задайте `RESERVATIONS_DRY_RUN=true`; в обычном запуске эта переменная должна отсутствовать или быть `false`.

Покупатель выбирает доставку или самовывоз по согласованию, указывает получателя и комментарий. Менеджер согласует стоимость и условия, сохраняет их в заказе, затем вручную подтверждает фактическую оплату. После оплаты стоимость доставки менять нельзя. `totalPrice` хранит сумму товаров, `deliveryPrice` — согласованную доставку отдельно; интерфейс показывает обе суммы и итог. Затем заказ можно отметить отправленным и доставленным. Номер отправления виден покупателю; внутренняя заметка менеджера — только администраторам.

При отмене оплаченного заказа выставляется «Ожидается возврат оплаты». Деньги возвращаются вручную вне сайта, после чего администратор отдельно подтверждает возврат. Нажатие кнопки само по себе деньги не переводит. Все изменения сохраняются в истории; уведомления покупателю и сообщения о новых/отменённых заказах менеджерам появляются в кабинетах.

Чтение каталога использует `use cache`, `cacheLife` и тег `catalog`. Изменения в админке и оформление заказов сбрасывают кэш. Персональные данные не кэшируются.

## Проверка

```powershell
npm.cmd run lint
npm.cmd run build
npm.cmd run test:integration
```

Интеграционный запуск сам собирает приложение в `.next-verify`, запускает production-сервер на порту 3001 и проверяет реальные HTTP Server Actions и изменения PostgreSQL. Создаются изолированные записи с префиксом `qa-`, которые удаляются в `finally`. Существующие заказы и товары не изменяются. После проверки останавливается только запущенный тестом сервер. При занятом порте задайте `$env:TEST_PORT='3002'`. Тесты используют ту же БД, поэтому запускайте их на локальной базе разработки.

Проверяются регистрация и сессия, роли и доступ, CRUD, фильтры, остатки, принадлежность корзины, одновременный перенос гостевой корзины, повторное оформление, снимки позиций заказа, отмена и конкуренция за последний экземпляр. Дополнительные проверки покрывают загрузку и перекодирование фото, отклонение SVG под видом JPEG, запрет покупки архивного товара, закрытость чужих заказов и внутренних заметок, согласование доставки, учёт возврата, уведомления и гонку отмены с истечением резерва. Проверяются также профиль и повтор заказа, фильтр характеристик, сравнение и публичные метаданные, проверенная покупка для отзывов, модерация и смена пароля с отзывом прежних сеансов. Адресная книга проверяется на принадлежность, лимит, выбор в корзине и конкурентную смену основного адреса. Всего 21 группа интеграционных проверок.

Если Prisma на Windows сообщает `EPERM` при замене DLL, остановите сервер разработки, использующий Prisma, и выполните `npx.cmd prisma generate`. Если сообщение относится только к DLL, TypeScript-типы при этом могут уже обновиться.

## Границы текущей реализации

Онлайн-эквайринг, тарифы перевозчиков и отправка писем/SMS не подключены: сервисы пока не выбраны. Уведомления доступны внутри сайта; внешних отправок нет. Доставка, оплата и возврат денег согласуются и выполняются вручную. Фотографии исходных товаров — **иллюстрации**; замените их своими реальными фотографиями через админку. Контакты магазина, адрес самовывоза и реальные условия продажи, доставки и обработки данных должны быть предоставлены владельцем до публичного запуска.

Восстановление забытого пароля и подтверждение почты остаются до подключения почтового сервиса. Пока доступна смена пароля из действующего аккаунта. Адресная книга поддерживает до 10 адресов: создание, изменение, удаление и основной адрес. Выбор в корзине подставляет получателя, телефон и адрес; их можно изменить только для текущего заказа. Основной адрес всегда один; при его удалении выбирается следующий. Адрес из профиля используется, если адресная книга пуста. История заказов хранит отдельные значения и не изменяется при редактировании адресов. Синхронизация избранного между устройствами пока не подключена. Контактные реквизиты, гарантийные условия и условия возврата не заполнены вымышленными данными.

Локальные иллюстрации загружены с Unsplash и обслуживаются через `next/image`: [гитара](https://images.unsplash.com/photo-1516924962500-2b4b3b99ea02), [клавишные](https://images.unsplash.com/photo-1520523839897-bd0b52f945a0), [студия](https://images.unsplash.com/photo-1598488035139-bdbb2231ce04), [акустическая гитара](https://images.unsplash.com/photo-1510915361894-db8b60106cb1). В админке также поддерживаются прямые HTTPS-ссылки `images.unsplash.com` и локальные иллюстрации `/images/*.jpg` из проекта.

`npm audit` на момент реализации сообщает о транзитивных уязвимостях инструментов Prisma v6 (`deepmerge-ts`) и ESLint (`minimatch`). Автоматическое исправление Prisma требует перехода на другую основную версию, поэтому v6 сохранена согласно AGENTS.md. Зависимость `@prisma/orm-postgres` из исходного проекта не используется приложением; запросы выполняются через `@prisma/client` v6.

Визуальная проверка в браузере в текущей среде недоступна из-за отсутствующего канала Computer Use. Адаптивные стили подготовлены, но ручная проверка мобильного интерфейса остаётся необходимой перед публикацией.
